## 四、协作规范

### 4.1 Git 分支管理

```
main (主分支)
  │
  └── develop (开发分支)
        │
        ├── feature/interview-service (成员A)
        ├── feature/question-bank (成员B)
        ├── feature/user-service (成员C)
        ├── feature/infrastructure (成员D)
        └── feature/frontend (成员E)
```

### 4.2 代码提交规范

```
feat: 新功能
fix: 修复Bug
docs: 文档更新
style: 代码格式调整
refactor: 重构
test: 测试相关
chore: 构建/工具相关
```

示例：
```
feat(interview): 实现面试会话管理API
fix(evaluation): 修复评估得分计算错误
docs(api): 更新接口文档
```

### 4.3 每日站会

**时间：** 每天上午 9:00 - 9:30

**内容：**
1. 昨天完成了什么
2. 今天计划做什么
3. 遇到什么问题

### 4.4 代码评审

- 每个 PR 需要至少 1 人 Review
- 核心模块需要 2 人 Review
- Review 时关注：代码规范、逻辑正确性、性能

## 八、质量保证

### 8.1 代码质量

- 后端代码覆盖率 > 60%
- 前端代码通过 ESLint 检查
- 关键模块需要 Code Review

### 8.2 功能测试

- 每个功能模块需要测试用例
- 集成测试覆盖核心流程
- 用户验收测试

### 8.3 性能测试

- 接口响应时间 < 2s
- 并发用户数 >= 100
- 内存占用合理
