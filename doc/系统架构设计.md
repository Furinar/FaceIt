# FaceIt 系统架构设计

## 一、架构概览

FaceIt 采用**前后端分离 + 微服务**架构，结合大语言模型（LLM）与检索增强生成（RAG）技术，构建智能化的 AI 模拟面试平台。

## 三、核心模块设计

### 3.1 用户服务模块

**职责**：用户注册、登录、信息管理

**核心功能**：
- 用户注册与登录（JWT 认证）
- 用户信息管理（学校、专业、意向岗位）
- 用户权限管理
- 密码加密存储（BCrypt）

**技术实现**：
- Spring Security + JWT
- Redis 存储 Token
- 密码加密：BCrypt

**接口示例**：
```
POST /api/auth/register    # 用户注册
POST /api/auth/login       # 用户登录
GET  /api/user/profile     # 获取用户信息
PUT  /api/user/profile     # 更新用户信息
```

---

### 3.2 面试服务模块

**职责**：面试会话管理、对话流程控制

**核心功能**：
- 创建面试会话（选择岗位、模式、时长）
- 管理面试状态（进行中、已完成、已中断）
- 记录对话历史
- 控制面试流程（自我介绍 → 技术提问 → 项目提问 → 场景题 → 行为题）

**技术实现**：
- WebSocket 实时通信
- 状态机管理面试流程
- 对话历史存储至数据库

**接口示例**：
```
POST /api/interview/create        # 创建面试会话
GET  /api/interview/{id}          # 获取面试详情
POST /api/interview/{id}/message  # 发送消息
POST /api/interview/{id}/end      # 结束面试
GET  /api/interview/history       # 获取历史记录
```

---

### 3.3 AI 推理服务模块

**职责**：大模型推理、动态追问、对话管理

**核心功能**：
- 调用大模型 API（智谱 GLM-4）
- 实现流式响应（SSE）
- 动态追问逻辑（关键词提取 + RAG 检索）
- 上下文记忆管理（保留最近 N 轮对话）
- Prompt 模板管理（岗位专属 System Prompt）

**技术实现**：
```python
SYSTEM_PROMPT = """
你是一位资深的 {job_position} 面试官，拥有 10 年以上的技术面试经验。
你的任务是对候选人进行专业的技术面试，评估其技术能力、项目经验和综合素质。

面试要求：
1. 根据候选人的回答进行深入追问，挖掘技术细节
2. 关注候选人的逻辑思维和表达能力
3. 模拟真实面试场景，保持专业且友好的态度
4. 每次提问前，先从知识库检索相关内容作为参考

当前面试阶段：{stage}
候选人背景：{user_background}
"""
```

**动态追问策略**：
1. 关键词提取：从回答中提取技术关键词（如 Spring Boot、Redis）
2. RAG 检索：根据关键词检索知识库，获取相关题目
3. 追问生成：结合检索结果与上下文，生成追问

**接口示例**：
```
POST /api/ai/chat          # 对话接口（流式响应）
POST /api/ai/evaluate      # 评估接口
```

---

### 3.4 RAG 知识库服务模块

**职责**：知识库构建、向量检索、内容召回

**核心功能**：
- 知识库文档切片与向量化
- 向量相似度检索
- 多路召回策略（向量检索 + 关键词检索）
- 知识库管理（增删改查）

**技术实现**：
```python
# RAG 流程
1. 文档切片：将长文档切分为 500 字左右的片段
2. 向量化：使用 Embedding 模型生成向量
3. 存储：向量存入 Milvus，元数据存入 PostgreSQL
4. 检索：根据用户输入检索 Top-K 相似片段
5. 重排序：根据相关性对检索结果重排序
6. 返回：返回最相关的 3-5 个片段作为上下文
```

**知识库结构**：
```
knowledge_base/
├── java_backend/
│   ├── tech_stack.md        # 技术栈清单
│   ├── interview_questions/ # 面试题库
│   │   ├── basic.md         # 基础题
│   │   ├── advanced.md      # 进阶题
│   │   └── project.md       # 项目题
│   └── best_answers/        # 优秀回答范例
└── web_frontend/
    ├── tech_stack.md
    ├── interview_questions/
    └── best_answers/
```

**接口示例**：
```
POST /api/knowledge/search    # 检索知识库
GET  /api/knowledge/list      # 获取知识库列表
POST /api/knowledge/upload    # 上传知识文档
```

### 3.5 评估服务模块

**职责**：面试表现分析、生成评估报告

**核心功能**：
- 多维度评分（技术正确性、逻辑严谨性、岗位匹配度、表达能力、自信度）
- 逐题点评
- 生成结构化报告
- 雷达图数据生成
- 改进建议生成

**评估维度**：
```python
EVALUATION_DIMENSIONS = {
    "technical_accuracy": {
        "name": "技术正确性",
        "weight": 0.30,
        "criteria": "知识点是否准确、是否有明显错误"
    },
    "logical_rigor": {
        "name": "逻辑严谨性",
        "weight": 0.25,
        "criteria": "表达是否有条理、是否使用 STAR 法则"
    },
    "job_matching": {
        "name": "岗位匹配度",
        "weight": 0.20,
        "criteria": "回答是否契合岗位要求"
    },
    "expression_ability": {
        "name": "表达能力",
        "weight": 0.15,
        "criteria": "语速、清晰度、流畅度"
    },
    "confidence": {
        "name": "自信度",
        "weight": 0.10,
        "criteria": "语气、情感状态"
    }
}
```

**技术实现**：
- 使用大模型进行长文本分析
- 提取关键指标（关键词覆盖率、回答完整度）
- 对比优秀范例进行评分
- 生成 JSON 格式的结构化报告

**接口示例**：
```
POST /api/evaluation/generate  # 生成评估报告
GET  /api/evaluation/{id}      # 获取评估报告
GET  /api/evaluation/history   # 获取历史报告
```

## 四、数据流设计

### 4.1 面试对话流程

```
用户 → 前端录音 → 音频流 → 后端 → ASR 服务 → 文本
                                    ↓
                              面试服务（记录对话）
                                    ↓
                              AI 推理服务
                                    ↓
                              RAG 检索（知识库）
                                    ↓
                              LLM 生成回复（流式）
                                    ↓
                              后端 → 前端（SSE 流式展示）
                                    ↓
                              TTS 服务 → 语音播放
```

### 4.2 评估报告生成流程

```
面试结束 → 后端触发评估
              ↓
        获取完整对话历史
              ↓
        AI 评估引擎分析
              ↓
        多维度评分 + 逐题点评
              ↓
        生成结构化报告（JSON）
              ↓
        存储至数据库
              ↓
        前端获取并可视化展示
```

## 五、部署架构

### 5.1 开发环境

```
本地开发：
- 前端：npm run dev (Next.js)
- 后端：Spring Boot (mvn spring-boot:run)
- 数据库：Docker Compose (PostgreSQL + Redis + Milvus)
```

### 5.2 生产环境

```
云服务器部署：
- 前端：Next.js 构建后由 Nginx 托管
- 后端：Docker 容器化部署
- 数据库：云数据库（RDS + Redis）
- 负载均衡：Nginx
- HTTPS：Let's Encrypt SSL 证书
```

### 5.3 Docker Compose 配置示例

```yaml
version: '3.8'
services:
  postgres:
    image: postgres:15
    environment:
      POSTGRES_USER: faceit
      POSTGRES_PASSWORD: faceit123
      POSTGRES_DB: faceit
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./sql/schema.sql:/docker-entrypoint-initdb.d/schema.sql

  redis:
    image: redis:7
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  milvus:
    image: milvusdb/milvus:v2.3-latest
    ports:
      - "19530:19530"
      - "9091:9091"
    volumes:
      - milvus_data:/var/lib/milvus

  backend:
    build: ./backend
    ports:
      - "8080:8080"
    depends_on:
      - postgres
      - redis
      - milvus
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/faceit
      SPRING_DATASOURCE_USERNAME: faceit
      SPRING_DATASOURCE_PASSWORD: faceit123
      SPRING_REDIS_HOST: redis

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    depends_on:
      - backend

volumes:
  postgres_data:
  redis_data:
  milvus_data:
```
